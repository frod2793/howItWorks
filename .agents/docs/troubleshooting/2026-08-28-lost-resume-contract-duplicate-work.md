# 기존 보고를 재개 계약으로 쓰지 않아 작업이 중복 생성됨

- 증상: 같은 worktree의 상태가 이미 보고됐는데도 새 터미널·새 에이전트·새 Editor 재기동을 반복했습니다. 결과적으로 한 worktree에 실행 주체가 누적되고, 검증은 같은 준비 실패를 반복했으며, 이전 dirty 변경의 소유자가 불분명해졌습니다.
- 환경: 다중 worktree를 여러 실행 주체가 병렬로 다루는 운영 환경.
- 원인: 보고를 단순 상태 메시지로 취급하고 다음 작업의 **재개 계약**으로 사용하지 않았습니다. 새 작업 시작 시 기존 실행 주체·작업 범위·마지막 성공 증거를 조회하지 않으면 같은 조사와 기동이 중복됩니다.
- 해결: (후보) 새 실행 주체를 만들기 전에 마지막 보고에서 아래 5항목을 읽어 전달 패킷에 그대로 복사하고, 기존 주체가 살아 있으면 새로 만들지 않고 재개 명령만 보냅니다.

```text
worktree 절대경로 / branch@SHA / dirty 기준선 개수
전용 Editor Name@hash 와 readiness 판정
마지막 성공 검증(job id) 또는 실패 로그 경로
현재 차단 사유 · 사용자 선택 필요 여부
다음 한 가지 재개 명령
```

- 검증: `not_run`. 절차 규칙이라 실행 가능한 검사가 없으며, 중복 생성 감소는 아직 실측하지 않았습니다.
- 재발 방지: 작업 시작·중단·재개 보고에 위 5항목을 필수로 남기고, 항목이 비면 보고를 완료로 처리하지 않습니다. 새 실행 주체가 불가피하면 exact 경로·범위·검증 job·금지 파일을 전달 패킷에 복사합니다.
- 승격 상태: 미승격 — 보고 템플릿으로 승격 예정.
