# Unity 특화 규칙 (Unity-Specific Rules)

> GEMINI.md §4.2~4.5 기반
> 이 문서는 URP 렌더링 파이프라인 관련 최적화 기술과 설정 방법을 정의합니다.

---

## 1. GPU Resident Drawer (GPU 레지던트 드로어)

중복 오브젝트가 많은 환경에서 드로우콜을 **수만 개 → 수백 개** 수준으로 극적으로 감소시키는 GPU 드리븐 렌더링 기술입니다.

### 작동 원리

| 기존 방식 | GPU Resident Drawer |
|----------|---------------------|
| 오브젝트마다 CPU가 드로우콜 명령서 생성 | 데이터를 **GPU 메모리에 상주** |
| CPU 병목 발생 | CPU 단 한 번 명령 → GPU가 처리 |
| 배치 렌더러 수동 설정 | **BRG(Batch Renderer Group)** 자동화 |

- 내부적으로 **컴퓨트 셰이더**를 통해 대량의 인스턴스를 병렬 처리합니다.
- 동일한 필터 세팅(셰도우 패스, 뎁스 패스 등)을 묶어 불필요한 검사를 건너뜁니다.

### 설정 방법

1. `Project Settings → Graphics` → 사용 중인 **URP 에셋** 선택
2. `GPU Resident Drawer`를 **Instanced Drawing**으로 변경
3. `Shader Stripping` 메뉴에서 `Batch Renderer Group` 설정을 **Keep**으로 변경
4. `Player Settings`에서 기존의 **Static Batching** 옵션을 **Off**로 비활성화

### 기대 효과

4K 해상도 마을 씬 테스트 기준, CPU 부하 감소로 프레임이 약 **30fps → 60fps** 이상(약 2배 향상)으로 개선된 사례가 있습니다.

## 2. GPU Occlusion Culling (GPU 오클루전 컬링)

카메라 시야에 들어오더라도 건물 등 큰 물체에 **가려져 보이지 않는 오브젝트**를 GPU에서 동적으로 제외하는 런타임 최적화 기법입니다.

### 핵심 메커니즘

| 기술 | 설명 |
|------|------|
| **투패스(Two-Pass) 알고리즘** | 이전 프레임 깊이 버퍼로 1차 컬링 → 현재 프레임에서 2차 검증·보정 |
| **바운딩 스피어(Bounding Sphere)** | 메시 대신 구체로 감싸 판정하여 연산 효율 향상 |
| **하이지 피라미드(Hi-Z Pyramid)** | 깊이 버퍼 해상도를 단계적 축소하여 비교 횟수 절감 |

### 적용 기준

| 상황 | 효과 |
|------|------|
| ✅ 건물 사이를 돌아다니는 씬 | 극적인 성능 이득 |
| ❌ 시야가 트인 오픈월드 | 투패스 오버헤드가 더 큼 (역효과) |
| ⚠️ 가로등·창살 등 얇고 긴 형태 | 바운딩 스피어 부정확 → 효율 저하 |

## 3. STP (Spatial-Temporal Post-processing) 업스케일링

화면을 저해상도로 렌더링한 뒤, **시간(Temporal)·공간(Spatial) 정보**를 모두 활용하여 고해상도로 업스케일하는 기술입니다.

### 발전 배경

```
SSAA → TAA → TAAU → STP
```

- TAA 구조에서 한 단계 더 발전하여 전 프레임 히스토리(Temporal)와 한 프레임 내 주변 픽셀 관계(Spatial)를 통합 활용합니다.
- **플랫폼별 자동 최적화**: 고성능 PC/콘솔 → 화질 극대화, 저사양 → 성능 확보

### 설정 방법

1. URP 에셋의 `Upscale Filter` 항목에서 **STP** 선택
2. `Render Scale`을 **1.0 미만** (예: 0.5 ~ 0.75)으로 설정
3. 카메라의 Anti-Aliasing 설정을 **TAA**로 지정

### 적용 가이드

| 항목 | 규칙 |
|------|------|
| **필수 전제** | 카메라 Anti-Aliasing이 반드시 **TAA** (FXAA/SMAA 비호환) |
| **Render Scale** | 0.5(성능 우선) ~ 0.75(균형). 1.0 이상에서 STP 비작동 |
| **모션 벡터** | 움직이는 오브젝트에 반드시 모션 벡터 생성 필요 |
| **커스텀 셰이더** | `MotionVectors` 패스 미구현 시 고스팅 발생 |
| **UI 오버레이** | Screen Space - Overlay → 영향 없음, Camera → 텍스트 선명도 저하 가능 |

### 디버깅 체크리스트

| 증상 | 원인 확인 |
|------|----------|
| 고스팅(Ghosting) | 해당 오브젝트의 모션 벡터 패스 누락 여부 |
| 화면 흐림/번짐 과다 | Render Scale 확인 (0.5 미만 비권장) |
| 깜빡임(Flickering) | 서브 픽셀 디테일에서 발생 → 알파 블렌딩 고려 |
| 특정 플랫폼 성능 저하 | Frame Debugger에서 STP 패스 GPU 타임 확인 |

## 4. Mesh LOD (메시 LOD) — Unity 6.2+

유니티 엔진 내부에서 자동으로 최적화된 LOD를 생성·세팅해 주는 기능입니다.

### 기존 LOD 그룹과의 차이

| 항목 | 기존 LOD Group | Mesh LOD |
|------|---------------|----------|
| 메시 준비 | 거리별 메시 수동 준비 | 자동 생성 |
| 메모리 | 정점 버퍼 수배 증가 | 정점 버퍼 **단 하나** 공유 |
| 전환 방식 | 메시 교체 | **인덱스 버퍼만** 교체 |
| 알고리즘 | — | **QEM(Quadric Error Metrics)** |

### 설정 방법 (Unity 6.2 이상)

1. 모델 에셋 인스펙터의 `Mesh LODs` 항목에서 **Generate Mesh LOD** 실행
2. `Limit LOD`를 체크하여 과도한 단계 생성 방지
3. 거리 전환 타이밍은 Quality Settings 또는 인스펙터의 바이어스 값으로 조절

### 적용 기준

| 상황 | 권장 |
|------|------|
| ✅ 동그란 덩어리 형태 (바위, 나무 수관) | Mesh LOD 효과적 |
| ❌ 길쭉하거나 각진 형태 | 기존 LOD 그룹 수동 제작 |
| ⚠️ 중요 에셋 | 기존 방식과 병행 사용 |

### 필수 전제

- **GPU Resident Drawer가 반드시 활성화**되어 있어야 Mesh LOD가 작동합니다.
