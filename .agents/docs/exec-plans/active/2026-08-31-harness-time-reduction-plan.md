**생성일**: 2026-08-31
**담당자**: 하네스 관리 세션
**관련 진단**: 2026-08-31 구조 진단 — 작업 시간 = 크기 무관 직렬 파이프라인 × 사람 승인 대기 × 워크트리 고정비 (실측: 소형 Task 3건 3일째 미완료, 승인·명시 요청 게이트 23곳, 시간 소모형 트러블슈팅 사례 4건)

## 목표와 완료 기준

- **목표**: 소형 Task의 착수→완료 벽시계 시간을 구조적으로 단축한다(파이프라인 왕복 수와 사람 승인 왕복 수를 절반 이하로).
- **완료 기준**: 각 Task의 규칙·문서·계약 테스트가 반영되고 세 스위트가 통과하며, 적용 후 소형 Task 1건 이상에서 왕복 감소가 실측 확인된다.
- **범위 밖**: 검증 권한·증거 기준의 완화(모든 개선은 기존 안전 게이트를 유지한다).

## 현재 실행 권한과 역할

문서·규칙·스크립트 작업이므로 Unity 실행 루트·Editor 항목은 전부 `N/A`. 현재 테스트 권한: 하네스 자체 스위트(run-tests.sh, run-workflow-tests.sh) 실행. 구현·검수는 기존 하네스 관리 절차(수정 후 서브 에이전트 교차 검수)를 따른다.

## 작업 단위

### Task 1: Task 크기 분류와 경량 트랙 (업무 계층) — 우선순위 1

- 업무 AGENTS.md에 Task 크기 분류 기준(소형: 문서·스펙 리뷰·단일 파일 저위험 수정 / 표준: 그 외)과 소형 전용 경량 트랙을 정의: 관리자+구현 2역할, 설계·설계검수 생략, 간이 완료 보고. 저위험 판정 기준과 표준 트랙 강제 승격 조건(공유 핫스팟 접촉, 신규 의존성 등)을 명시.
- 완료 기준: 규칙 문면 + 계약 테스트 + 배포.

### Task 2: 승인 배칭(사전 위임) (업무 계층) — 우선순위 1

- 계획 승인 시점에 검증 권한·수치 허용 범위를 함께 확정하는 "사전 위임 블록"을 계획 템플릿과 규칙에 추가(예: "이 Task 범위 내 EditMode 테스트 실행을 사전 승인"). 위임되지 않은 항목만 개별 승인.
- 완료 기준: 템플릿·규칙 문면 + 계약 테스트 + 배포.

### Task 3: 행 감지 타임아웃 규칙 (공유 계층) — 우선순위 2

- 과거 트러블슈팅 사례 3건(옛 MCP 연결의 stale 인스턴스 대기, Editor 모달 정지, 빌드 job 소실)의 timeout 정책을 Pipeline 경로에도 적용하도록 규칙으로 승격: 외부 응답 대기 상한(기본 3분), 초과 시 중단·사례 기록·복구 절차 진입. 해당 사례 status를 promoted로 갱신.
- 완료 기준: 규칙 문면 + 사례 승격 + 계약 테스트 + 배포.

### Task 4: 워크트리 풀 재사용 (공유 계층) — 우선순위 3

- worktree 생성 규칙에 재사용 절차 추가: 작업 종료 시 삭제 대신 정리(브랜치 전환·clean) 후 유휴 풀 유지, 신규 Task는 유휴 워크트리 우선 재할당(Library 재복사·Editor 재부팅 고정비 회피). 정리 기준과 오염 시 폐기 조건 명시.
- 완료 기준: 규칙 문면 + 계약 테스트 + 배포.

### Task 5: 검증 배칭 (공유 계층) — 우선순위 3

- 동시 검증 실행 규칙에 배칭 지침 추가: 연관 Task의 테스트 요청을 모아 배치 Editor 1회 기동으로 실행(run-parallel-tests.sh 활용), 콜드스타트 고정비를 Task 수로 분할.
- 완료 기준: 규칙 문면 + 계약 테스트 + 배포.

## 검증 계획

- 각 Task 반영 후: 범용·업무 run-tests.sh, 업무 run-workflow-tests.sh 통과, COMMON_EXPECTED_HASH 재고정, 보호 필터 동기화 배포, 서브 에이전트 교차 검수.
- 효과 실측: 적용 전후 소형 Task 1건의 역할 왕복 수·승인 왕복 수 비교 기록(트러블슈팅 사례 양식).
