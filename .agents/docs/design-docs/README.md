# 설계 문서 작성 가이드

## 언제 작성하는가

- 새로운 기능·시스템을 구현할 때
- 프로젝트 경계나 의존 방향을 변경할 때
- 여러 씬·모듈에 영향을 주는 리팩터링을 할 때
- 디자인 패턴 또는 성능 설정을 도입·변경할 때

파일명은 `YYYY-MM-DD-기능명-design.md` 형식을 사용하고 [_TEMPLATE.md](_TEMPLATE.md)를 복사합니다.

## 프로필 기반 작성 계약

1. `.agents/config/project-profile.conf`의 `confirmation_status`를 기록합니다.
2. 생성·수정 경로는 `${source_root}`, 테스트 경로는 `${test_root}`를 사용합니다.
3. 아키텍처 표에는 `선택 프로필의 역할`과 실제 `클래스`를 연결합니다.
4. `dependency_injection=none`도 정상 선택으로 취급하고 객체 조립 위치를 기록합니다.
5. 최적화는 `적용 상태`, `측정 근거`, `롤백 조건`을 함께 기록합니다.
6. Open Questions는 실제 미결정 사항이 있을 때만 작성합니다. 결정이 끝났으면 섹션을 삭제합니다.

`test_root`가 비어 있으면 임의 테스트 폴더를 만들지 않고 대체 검증 방법을 명시합니다.

## 작성 프로세스

1. 프로필과 관련 [아키텍처 Profile](../profiles/architecture/)을 확인합니다.
2. 템플릿을 복사하고 모든 적용 섹션을 구체적인 근거로 채웁니다.
3. 의존 방향, 실패 처리, 성능 측정·롤백을 검토합니다.
4. 사용자 승인을 받은 뒤에만 실행 계획과 구현으로 이동합니다.

## 완료 체크리스트

- [ ] 프로필 상태와 선택값을 사실대로 기록했는가?
- [ ] 선택된 아키텍처의 허용·금지 의존 방향을 지켰는가?
- [ ] `${source_root}`와 `${test_root}`가 실제 프로필 값과 대응하는가?
- [ ] DI가 없을 때의 Composition Root도 설명했는가?
- [ ] 최적화 결정을 수치와 롤백 기준으로 검증할 수 있는가?
- [ ] 해결된 Open Questions와 빈 선택 섹션을 제거했는가?
